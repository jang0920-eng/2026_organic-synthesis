# Yield-BERT 수율 예측 (소토라십)

모델: [rxn_yields](https://github.com/rxn4chemistry/rxn_yields) — Schwaller et al.,
*Mach. Learn.: Sci. Technol.* **2021**, 2, 015016.
사용한 가중치: `suzuki_miyaura` random split 10개 앙상블, CPU 추론.

입력은 AiZynthFinder v4의 route 1(10단계)·route 6(12단계) 반응 SMILES 22개다.

## 1. 어느 모델을 쓸 수 있는가

repo에 학습된 모델 세 종류가 동봉되어 있다(818MB). 별도 다운로드는 필요 없다.
그런데 **모델 출력은 표준화된 값이라, 학습 세트의 mean·std로 역표준화해야 수율(%)이 된다.**
이 보정 상수를 구할 수 있느냐가 사용 가능 여부를 가른다.

| 모델 | 학습 데이터 | 보정 가능? | 판정 |
| --- | --- | --- | --- |
| `suzuki_miyaura` | HTE Suzuki 커플링 (repo 동봉) | 가능 (mean=0.4033, std=0.2819) | **사용** |
| `buchwald_hartwig` | HTE C–N 커플링 (repo 동봉) | 가능 | 이 경로에 Pd 촉매 C–N 커플링이 없어 해당 없음 |
| `uspto` | USPTO 수율 (IBM Box) | **불가능** | 학습 데이터가 로그인이 필요한 Box에 있어 mean·std를 알 수 없다 |

즉 **범용 수율 모델은 쓸 수 없고**, 특정 HTE 실험으로 학습된 모델만 남는다.
이것이 이 단계의 가장 큰 제약이다.

## 2. 실행

```powershell
conda activate parrot-env          # Parrot과 같은 스택(rxnfp + simpletransformers)을 쓴다
python scripts/run_rxn_yields.py --route 1 6 --splits 10
```

Windows에서 고쳐야 했던 두 가지다.

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `AttributeError: 'SmilesClassificationModel' object has no attribute 'loss_fct'` | rxnfp 0.1.0이 옛 simpletransformers 기준으로 작성되어 이 속성을 설정하지 않는다 | `model.loss_fct = None`을 넣어 기본 손실함수를 쓰게 한다 (회귀 예측값에는 영향 없음) |
| 피처 변환이 배치당 30초 이상 | Windows에는 fork가 없어 멀티프로세싱이 spawn으로 뜬다 | `use_multiprocessing: False`, `process_count: 1` |

## 3. 결과

22개 단계 전부 **15.3 ~ 47.3%** 안에 들어오고 평균이 26.3%다.
앙상블 10개의 표준편차는 평균 **±9.4%p**로 매우 크다.

| 구분 | 단계 수 | 예측 수율 평균 |
| --- | --- | --- |
| Suzuki 커플링 (학습 도메인) | 4 | **19.4%** |
| 그 외 (학습 도메인 밖) | 18 | 27.8% |

단계별 표는 `route_1_yields.md`, `route_6_yields.md`에 있다.

## 4. 실제 공정 수율과의 비교

`HANDOFF.md` 6장의 Amgen 공정 수율이 ground truth다.

| 반응 | 실제 수율 | 모델 예측 | 차이 |
| --- | --- | --- | --- |
| Suzuki–Miyaura 커플링 | **80%** | 17.8 ± 5.3% | **−62%p** |
| 염소화 + 피페라진 SNAr (원포트) | 66% | 27.7 ± 13.9% (염소화) / 22.2 ± 9.1% (SNAr) | −38~44%p |
| Pd 제거 + Boc 탈보호 | 94% | — (경로에 대응 단계 없음) | — |
| 전체 (5단계 기준) | 65% | — | — |

**모든 단계에서 크게 과소평가한다.** 특히 실제로 80%가 나오는 Suzuki 커플링을
17.8%로 예측했다. 이 단계는 모델의 학습 도메인(Suzuki)에 속하는데도 그렇다.

## 5. 한계점 (보고서용)

1. **범용 수율 모델을 쓸 수 없다.** USPTO로 학습한 범용 모델이 repo에 있지만, 보정에 필요한
   학습 데이터가 로그인이 필요한 외부 저장소에 있어 출력을 수율(%)로 환산할 수 없다.
   공개된 수율 모델이 실제로는 **특정 HTE 실험 전용**이라는 뜻이다.

2. **학습 도메인 밖 단계에도 아무 경고 없이 숫자를 낸다.** 22개 중 18개가 Suzuki가 아닌데도
   모델은 전부 값을 냈다. 그중에는 route 1의 3단계 — 아세틸 클로라이드로 융합고리를 만드는,
   **실제로 일어나지 않는 반응** — 도 포함되어 15.3%라는 값을 받았다.
   존재하지 않는 반응의 수율이 예측된 것이다.

3. **Suzuki 단계를 구분하지 못한다.** 학습 도메인인 Suzuki 단계의 평균 예측(19.4%)이
   도메인 밖 단계 평균(27.8%)보다 오히려 **낮다.** 모델이 자신이 아는 반응을 알아보지 못한다.
   HTE 데이터는 기질이 고정되고 리간드·염기만 바뀌는 조합이라, 기질 구조가 전혀 다른
   소토라십 중간체에는 학습한 패턴이 적용되지 않는다.

4. **예측이 학습 세트 평균 쪽으로 쏠린다.** 학습 세트 평균이 40.3%인데 예측값이 전부
   15~47% 구간에 몰린다. 실제 공정의 80%·94% 같은 고수율도, 분할 단계의 37% 같은
   저수율도 재현하지 못한다. 회귀 모델이 확신이 없을 때 평균을 내놓는 전형적인 양상이다.

5. **불확실성이 예측값만큼 크다.** 앙상블 편차가 평균 ±9.4%p이고 최대 ±13.9%p다.
   예측값 자체가 15~47%인 것에 비하면 구간이 지나치게 넓어, 단계 간 우열을 가리는 데
   쓸 수 없다.

### 파이프라인 전체에 대한 결론

경로(AiZynthFinder) → 조건(Parrot) → 수율(Yield-BERT)로 이어지는 동안
**뒷단 모델이 앞단의 오류를 한 번도 걸러내지 않았다.**

- 경로 모델은 원자 수지만 맞추고 메커니즘을 보지 않았다 (한계점 1)
- 탐색 점수는 화학적 타당성을 재지 않았다 (한계점 6)
- 조건 모델은 불가능한 반응에 표준 조건을 냈다 (`results/parrot/README.md` 2번)
- 수율 모델은 그 불가능한 반응의 수율까지 예측했다 (위 2번)

route 1의 3단계 하나가 세 모델을 모두 통과했다. 각 모델이 자기 영역의 수치만 최적화하고
화학적 타당성은 누구도 검증하지 않는다는 것을, 같은 분자·같은 경로에서 끝까지 추적한 사례다.
